# Title

Dynamic memory allocation

# Status

Accepted

# Context

To implement the feature of independant module compilation, the kernel needs to have a way to allocate memory dynamically as **we do not want the kernel to have prior knowledge of how many tasks will run on the system**.

# Decision

First, we reserve a section in the memory mapping which will be used for the heap :

```C                            
     0x80800000 ┌───────────────┐ 
                │               │ 
       ▲        │               │ 
 3 MB  │        │      heap     │ 
       ▼        │               │ 
                │               │ 
     0x80500000 ├───────────────┤ 
                │               │ 
       ▲        │               │ 
       │        │               │ 
       │        │               │ 
       │        │       .       │ 
 4 MB  │        │       .       │ 
       │        │       .       │ 
       │        │               │ 
       │        │               │ 
       ▼        │               │ 
                │               │ 
     0x80100000 ├───────────────┤ 
                │               │ 
       ▲        │               │ 
       │        │               │ 
 1 MB  │        │     kernel    │ 
       │        │               │ 
       ▼        │               │ 
                │               │ 
     0x80000000 └───────────────┘ 
```

Here we allocate 3 MB of memory for dynamic allocation. Then we only allocate **4K pages** which is the size of each **task stack**. There is **no way to free memory**.

A protection is implemented to prevent allocating pages outside of the heap section.

# Consequences

The allocator implementation is very basic and so have many limitations, the implementation of a **binary buddy system** is more suited for a full-featured allocator.

Also, this API only allocates *4K memory pages** (also called **coarsed-grained allocation**), we should design an another API for **fine-grained allocation**.
